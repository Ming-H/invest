# tenscreener 设计文档

> 十倍股筛选器:融合 CAN SLIM + 静水,三级漏斗,全市场 → 1-2 只最具 10 倍潜力的股票。

## 1. 目标与北极星

不是产出名单,而是**逐轮收紧、收敛到 1-2 只"业务体量能增长 10 倍"的超级成长股**(静水核心)。
按**数据获取成本分层**:便宜数据(问财)广撒网,贵数据(财报/研报)精砸幸存者。

## 2. 三级漏斗

| 级别 | 数据 | 筛什么 | 留多少 |
|---|---|---|---|
| L1 问财初筛 | 问财(纯量化) | 营收同比≥50% + 总市值<300亿 + **严格早期价格带**(近1年<30% + 近3年<100% + 近6月>10% + 距ATH<75%)+ 扣非为正 + 排雷标记 | 5000→~10-20 |
| L2 深度体检 | 问财补全 + cninfo财报 | CAN SLIM 七要素 + 静水清单打分 + 缺口标注 | →5-10 |
| L3 十倍评估 | 研报 + 行业 + 财报 | TPS 七因子(F1/F5/F6 由 Claude 定性) | →1-2 |

## 3. TPS 十倍潜力分

```
TPS = 0.30·F1行业空间 + 0.20·F2终点可达 + 0.15·F3市值衰减
    + 0.15·F4成长性 + 0.10·F5催化 + 0.05·F6生意模式 + 0.05·F7估值
```
- F2/F3/F4/F7 脚本算;F1/F5/F6 Claude 定性
- **F3 市值 = `100·exp(-市值/800)`,减分不否决**

## 4. 关键设计决策(及其理由)

1. **三线多季序列(2026-08-30 修订,替换旧"近8季度营收环比加速")**:旧方案(逐只逐年查累计营收差分成单季,15 只 ≈45 次查询,只覆盖营收一条线,且环比口径混季节性)废弃。新方案用问财语法「**近四个季度单季 营收/归母/扣非 同比增长率**」一次取三线四季(15 只 ≈3 次查询)。理由:①若羽臣复盘特征3——营收与利润会错位(24Q4 营收+14%掉线、利润+133%过线),必须三线分别看;②同比口径免季节性干扰;③省额度 15 倍。**单季掉线不剔除,只进排序权重(过线条数,连续季数,营收同比)**——忠于两框架字面法则,不自行衍生苛刻条件。加速语义保留在 `quarters.yoy_accel`(同比口径)。
2. **不卡市值硬阈值**:用「空间驱动(F1)+ 终点对标(F2)+ 软评分(F3 非线性减分)」替代。大市值靠"空间不足/赔率低"自然淘汰,而非一刀切。
3. **两步法**:问财的"逐年递增""扣非>0""增速上限"判定都不可靠 → 粗筛后由脚本自算验证。
4. **问财字段鲁棒匹配(`_pick` + 正则)**:问财返回字段名/日期动态变化,用候选列表 + 模糊匹配 + 正则(单季字段)容错;`--dump-raw` 打印原始 key 排查漂移。
5. **严格早期价格带(避开已涨 10 倍/高位)**:L1 用**上限涨幅**而非下限——近1年<30% + 近3年<100% + 近6月>10% + 距历史最高<75%。这是"scout 错杀筛选"哲学:找**业绩已过线、股价还没看见**的标的(若羽臣 24Q3 状态);"看见"的确认交给 watch 阶段(pos_1y≥0.95),两阶段互补而非矛盾。阈值均可经 CLI 调。
6. **全部查询收口 wencai.py(2026-08-30 新增)**:当日缓存(md5(归一化query|limit))、API 计数与 query 清单、离线回放模式(fixtures 缺失即抛 FixtureMissing——防 query 漂移的哨兵)。额度:一天全部子命令 ≈15-18 次查询,同日重跑 0 次。

## 5. 已知局限(需 Claude 在 L3 甄别)

- **严格"增速逐年递增"天然偏向拐点/周期/低基数股**(净利暴增几千%):如黄金/钨/旅游扭亏/重组股会进 L1,L2/L3 需用 F1(行业空间)把它们压下去。
- **F1/F5/F6 必须由 Claude 读研报/财报定性**,脚本只给占位 50。
- **机构明细/外资/供求信号**:问财拿不全,需 cninfo 财报 + 东方财富补。

## 6. 数据流

```
问财(L1 量化 + L2 补全) ──► cninfo 财报 PDF(L2 供求信号) ──► 研报(L3 行业空间/催化)
                                                                          │
                                                                   Claude 定性回填 F1/F5/F6
                                                                          │
                                                                   TPS 收敛 → 1-2 只
```

## 8. 生命周期监测(2026-08-30 新增,源自若羽臣 003010 十倍全程复盘)

复盘锚点(低点 3.92 → 高点 47.83,+1121%,约 20 个月):

| 若羽臣时间线 | 生命周期阶段 | 实现 |
|---|---|---|
| 24Q3 三线首过线、股价近1年仍 -18% | **scout**(L1 错杀筛选) | L1 严格早期价格带(原有) + 三线序列(新) |
| 24/10底披露 → 24/11 启动 | **watch 确认** | R1 持续超预期(≥2线≥40) + R2 pos_1y≥0.95 + R3 大盘 on;R4 两期全不过→证伪 |
| 25/4 年报+一季报连续过线 → 主升加速 | "连续验证"注记 | R1 的 streak≥2 加注(资金合力) |
| 26/4 增速 123→111→73 + 回撤49%,三线仍全过 | **track** | E1 单季降档→warn;E3 回撤裁定:基本面过线→**扛住(warn)**,fail→exit。真实数据判 warn 而非 exit,事后 26Q3 反弹+25% 佐证阈值不过拟合 |

设计要点:
- **scout 找"财报已看见、股价还没看见";watch 等"股价也看见了"**——正是静水"看见>分析"的两段式落地
- **exit_signal 是告警不是指令**;建仓/清仓永远人工(不荐股)
- peak 维护:历史峰值/现价/近一年最高三者取大(漏跑期间创新高也不丢)
- watch/track 单次运行 ≈5 次查询(10 只:指数 1 + 三线 2 + 价格 2,当日缓存复用)
- 出处映射与"量化近似"参数清单见 `references/lifecycle.md`
## 9. runner 右侧趋势中继(2026-08-30 新增:上涨期间识别)

**分工**:scout 抓"若羽臣型"错杀反转(业绩先行股价未动),价格闸按设计挡掉一切已走出标的;runner 抓"中际旭创型"主线动量(正在上涨)。两条通道互补,分别对应静水的左侧洞察("低位被错杀的优质成长等财报验证→戴维斯双击")与右侧主做模式(趋势投资/景气跟随:"看见>分析""越高越安全""等回调分仓介入")。

**数据策略**:问财只花 1 次在全市场条件粗筛(近1年>60% & 双线同比>40% & 市值<800亿 & 申万行业);动量精确值(pos_1y/52周低点倍数/回撤)全部由腾讯前复权K线离线自算(kline.py,免额度,含分段合并与缓存);三线序列复用 quarters;大盘复用 market_gate。单次全流程问财 ≈4-8 次。

**五阶段判定**(出处见 references/lifecycle.md):主升期/强势待确认/回调击球区/深调考验区/退潮;不设涨幅上限("越高越安全")。排序 (阶段, 板块共振数, streak, 归母同比)。

**验收**(tests/test_runner_replay.py 真实数据回放,含披露滞后对齐防未来函数):
- 若羽臣首亮 2024-08 击球区(1.49x,其后+806%);2024-11 主升期=真实启动月;2026-08 击球区=当前真实状态
- 中际旭创首亮 2024-05 击球区(1.88x→+1179%);2024-06 强势待确认(大盘off,精确对应熊市尾端α孤军);2025-02~05 深调考验区(回撤46-56%但三线仍过,"扛住"区);2025-07/08 主升期

**watch 集成**:runner 亮灯名单可 `watch import --from-runner` 入池(仅 主升期/击球区/待确认 三态),入池后 confirm_check 的 R1/R2/R3 与 runner 阶段天然一致。
